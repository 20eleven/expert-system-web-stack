# Отчёт
## Прототип экспертной системы «Выбор технологии для веб-проекта»

### 1. Описание созданной экспертной системы

Разработан прототип экспертной системы, предназначенной для автоматизации принятия решений при выборе технологии реализации веб-проекта.

Система ориентирована на начинающего веб-разработчика и руководителя проекта, принимающих решение о способе реализации проекта на этапе до его запуска. Ошибка такого выбора может привести к рефакторингу проекта, срыву сроков и перерасходу бюджета.

Ввод данных выполняется по шести признакам:
- тип проекта: лендинг, корпоративный сайт, интернет-магазин, веб-сервис, портал университета
- бюджет: низкий, средний, высокий
- срок реализации: до двух недель, один-два месяца, более двух месяцев
- необходимость административной панели для редактирования контента: да, нет
- ожидаемая нагрузка: до 500, от 500 до 10 000, более 10 000 пользователей в сутки
- компетенции команды: PHP, JavaScript (Node.js), Python, разработчики отсутствуют

Результат включает тип решения (статический сайт, готовая CMS, разработка на фреймворке), рекомендуемый стек технологий, хостинг и инфраструктуру, предупреждения о рисках. а также объяснение процесса принятия решения в виде списка сработавших правил.

База знаний размещена в файле `kb.clp` и содержит шаблоны фактов `answers` (входные данные), `platform` (промежуточное заключение о типе решения), `rec` (рекомендация) и `why` (шаг объяснения).
<br>
20 правил базы знаний, объединённых в четыре уровня: 
<br>
R1–R7 определяют тип решения,
<br>
R8–R14 формируют стек с учётом компетенций команды, 
<br>
R15–R18 определяют хостинг и инфраструктуру с учётом нагрузки, 
<br>
R19–R20 формируют предупреждения при конфликте бюджета и срока сразработкой. 
<br>
Пример правила R5: если тип проекта — интернет-магазин и бюджет не является низким,
то тип решения - разработка на фреймворке.

Механизм логического вывода реализован с помощью оболочки CLIPS: вывод прямой, от исходных данных к заключению, выполняется через RETE. Правила второго, третьего и четвёртого уровней срабатывают от промежуточного факта `platform`, формируемого правилами первого уровня.

Интерфейс пользователя выполнен как одностраничное веб-приложение и обеспечивает ввод данных через выпадающие списки, получение результата в разделах Тип решения, Стек, Хостинг и инфраструктура, Предупреждение, а также просмотр объяснения принятого решения.

### 2. Использованные инструменты и технологии

В качестве оболочки экспертной системы выбрана CLIPS: открытый код, отсутствие лицензионных
ограничений, актуальный механизм вывода по алгоритму RETE и наличие
библиотеки для Python.

Стек:
- Python 3 — язык реализации приложения
- CLIPS 6.4 — оболочка экспертной системы: хранение базы знаний и логический вывод
- clipspy — подключение оболочки CLIPS к приложению на Python
- Flask — веб-сервер, обработка запросов и передача данных в механизм вывода
- HTML, CSS — формирование страницы, отображение результата и объяснения

Состав проекта: 
<br>
`kb.clp` — база знаний
<br>
`app.py` — механизм вывода и маршрутизация
`templates/index.html` — интерфейс пользователя
<br>
`test.py` — тесты
<br>
`requirements.txt` — перечень зависимостей.

### 3. Результаты тестирования

Тестирование выполняется скриптом `test.py` и охватывает все типы проектов, все варианты
компетенций команды, а также крайние значения бюджета, срока и ожидаемой нагрузки.
Критерием успешного прохождения является совпадение фактической рекомендации с ожидаемой
по каждому сценарию; итоговая строка прогона при отсутствии расхождений — «8/8 тестов пройдено».

| Тест | Ключевые входные данные | Ожидаемый результат |
|---|---|---|
| T1 | лендинг, административная панель не требуется, разработчики отсутствуют | статический сайт, стек HTML/CSS/JS или Hugo |
| T2 | корпоративный сайт, PHP | CMS, стек WordPress + MySQL |
| T3 | интернет-магазин, низкий бюджет, JavaScript | CMS, стек WordPress + MySQL |
| T4 | интернет-магазин, средний бюджет, PHP | заказная разработка, стек Laravel + MySQL |
| T5 | веб-сервис, JavaScript, высокая нагрузка | заказная разработка, хостинг VPS с Redis и CDN |
| T6 | портал университета, Python | заказная разработка, стек Django + DRF |
| T7 | веб-сервис, разработчики отсутствуют, низкий бюджет, срок до двух недель | no-code или подрядчик, предупреждения по бюджету и сроку |
| T8 | лендинг, высокая нагрузка | хостинг VPS и CDN без рекомендации статического хостинга |
